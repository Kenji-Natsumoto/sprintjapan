# X マーケティング（Closed Loop 1）

- 目的: 論文、ニュース、イベント、BOT の開発進捗を X で発信し、問い合わせと登壇機会を生む
- 入力:
  - 公開済みの論文とニュース（sprintjapan.net のインサイトとニュース、sprintjapan.com の記事）
  - 開発の進捗（`bot/` の変更履歴のうち機密を含まないもの。Building in Public の素材）
  - イベント情報（湯川塾分科会、セミナー、ワークショップ）
  - X 上の反応データ（表示数、反応数、プロフィール訪問、リンククリック、返信の内容）
- 出力:
  - 投稿案（1 日 1〜3 本）。`prompt.md` の出力契約に従う JSON
  - 投稿（署名後）
  - 週次分析と次週の方針（`weekly-review.md` の出力契約に従う）
- 頻度: 投稿案は毎日朝、投稿は署名後に指定時刻、分析は毎週月曜
- 実行役: 第一候補 Grok（X との近さ、反応データへのアクセス）／代替 どのモデルでも可。同じ `prompt.md` で動く
- 鍵の範囲: X の API のみ。GitHub、Supabase、Drive、Gmail の鍵は持たない
- 機密区分: なし。クライアント名、対話ログ、提案内容、金額は入力に含めない。入力に混入していたら投稿案を作らず停止する
- 署名が要る判断:
  - 立ち上げから 4 週間は全投稿
  - 5 週目以降、定型投稿（論文の一節の紹介、ニュースの告知）は自動。意見表明と他者への言及は署名
  - 返信は常に署名
- 成果指標: 問い合わせ数（月）、フォロワーの増分（週）、論文ページへの流入（週）、登壇や取材の依頼数（月）
- プロンプト: `prompt.md`（投稿案）、`weekly-review.md`（週次分析）
- 停止条件:
  - 否定的な返信が 1 投稿に 5 件以上ついた
  - 誤情報や事実誤認の指摘を受けた
  - 入力にクライアント名や機密が混入した
  - 同じ内容の投稿案が 3 日連続で出た（素材切れ）
  いずれも自動停止し、理由と再開に必要な判断を一文で夏本に通知する

## 試験運用の設計（Grok を実行役にする最初の 2 週間）

1. 1 週目: 投稿案の生成だけを Grok に任せ、投稿はしない。夏本が採点（1〜5）と修正文を残す。採点書式は `bot/eval/day3-test-set.md` と同じ
2. 2 週目: 採点 4 以上の型だけ投稿に回す。全件署名
3. 判定: 2 週間の平均点が 3.5 以上、かつ停止条件に一度も当たらなければ本運用へ。下回れば `prompt.md` を直してもう 1 週
4. 比較: 同じ素材で別のモデルにも投稿案を作らせ、同じ採点表で比べる。実行役の決定は採点で行う
