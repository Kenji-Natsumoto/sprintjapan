# X 週次分析プロンプト v0.1

> 毎週月曜に実行役に渡す。入力は先週の投稿と反応データ。出力は次週の方針。

## 0. 目的

先週の投稿を型ごとに振り返り、何が効いて何が効かなかったかを数字で言い、次週の方針を三つの仮説にする。
分析は「効率性より効果性」で行う。表示数が多かったかではなく、問い合わせや論文への流入につながったかを見る。

## 1. 入力（実行時に差し込む）

- 先週の投稿一覧（型、本文、投稿時刻、署名の有無）: {{posts}}
- 投稿ごとの反応（表示、反応、プロフィール訪問、リンククリック、返信の要旨）: {{metrics}}
- 週の成果指標（問い合わせ数、フォロワー増分、論文ページ流入、依頼数）: {{weekly_kpi}}
- 先週の方針と仮説: {{last_policy}}

## 2. 出力契約

```json
{
  "week": "YYYY-Www",
  "by_type": [
    { "type": "反論", "posts": 2, "impressions": 0, "link_clicks": 0, "inquiries": 0, "verdict": "効いた | 効かなかった | 判定不能", "why": "一文" }
  ],
  "best_post": { "text": "本文", "why": "一文" },
  "worst_post": { "text": "本文", "why": "一文" },
  "last_hypotheses_result": [
    { "hypothesis": "先週の仮説", "result": "支持 | 棄却 | 判定不能", "evidence": "一文" }
  ],
  "next_policy": {
    "type_mix": { "論文の一節": 2, "反論": 2, "進捗": 2, "そもそも": 1, "告知": 0 },
    "best_times": ["HH:MM", "HH:MM"],
    "hypotheses": ["次週に検証する仮説 1", "仮説 2", "仮説 3"],
    "promo_quota": 1
  },
  "flags": ["否定的な返信が集まった投稿があれば本文と件数", "誤情報の指摘があれば内容"]
}
```

## 3. 規則

1. 表示数だけで「効いた」と言わない。リンククリックと問い合わせを優先する。
2. 判定不能なら判定不能と書く。数が少ない週に無理に結論を出さない。
3. 仮説は必ず三つ。一つは「型」、一つは「時刻」、一つは「語り方」について。
4. `flags` に何か入ったら、次週の方針より先に夏本に通知する。
