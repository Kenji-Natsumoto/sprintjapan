# 夏本BOT（MVP 1〜3 日目の設計資産）

夏本健司の知識・判断軸を継承し、マッキンゼー流の構造化と a16z 流の投資家視点を併せ持つ事業創造パートナー BOT。
最初のプロトタイプは **新規アプリ**として作る。lumora-v2（音声で記録し、経過を見て、渡し紙で外に出すアプリ）は単体アプリとして残し、その資産（音声入力、音声アンロック、タブ骨格、端末内保存、渡し紙の描画）をコピーして流用する。

## 設計の中心

クライアントの多くは「問い」を持っていない。
だから BOT は答えるのではなく、**確かめるべき問いを一つ作って手渡す**。
入口はデザインスプリントではなく、サービスアイデアシートの 5 項目（顧客属性 → 顧客課題 → 現在使っているサービス → ソリューションコンセプト → 名前）。
5 項目が埋まったら、開発を勧めずプロブレムインタビュー（顧客発見）を勧める。

セッションの成果物は「シート一枚、問い一つ、次の行動一つ」。

## 3 日の割り当て

1. **1 日目**: 「話す」を BOT 先攻に変える。`system-prompt.md` を投入。応答 JSON の `speak` を音声合成、`text` と `diagram` を画面へ。`sheet_update` を状態に反映。
   AI ネイティブの論文（このリポジトリの `src/pages/*.tsx` にある 7 本）を検索対象に入れ、`{{knowledge_context}}` に差し込む。
2. **2 日目**: 「経過」にセッション状態を保存。「渡し紙」でシート一枚を描画。Mermaid を描画（描画前に構文検査、失敗時は再生成）。
3. **3 日目**: `eval/day3-test-set.md` の 10 問を本人が投げ、採点し、`turns[].override` に残す。合格ラインを下回った節を直す。

## 音声層（決定済み）

- 音声合成: ElevenLabs。夏本本人の声を複製した音声で `speak` を読み上げる。
  - 1 日目: 即時複製（短い録音）で試す。文単位のストリーミングで最初の一文を先に出す。
  - 4 日目以降: 高精度複製（30 分以上のきれいな録音）に差し替える。録音は「短い問いかけ」の口調で行う。講演口調で録ると BOT の問いが不自然になる。
  - 録音セッションは決まり文句の採取を兼ねる。`prompts/judgment-rules.md` 末尾の未確定欄に書き足す。
- 音声認識: 1 日目はブラウザの Web Speech API（日本語）。精度が問題になったら層ごと差し替える。ElevenLabs の認識（Scribe）も候補。
- 会話の間合い（割り込み、発話区切り）: 1 日目は押して話す方式。第 7〜8 週で ElevenLabs Agents の「外部 LLM 接続」を評価し、間合いだけを任せる案を検討する。核（Claude API と応答 JSON）は変えない。
- 開示: 初回セッションの冒頭で合成音声であることを一度だけ伝える（`system-prompt.md` 第 11 節）。

## 3 日で作らないもの

ログイン、クライアント別ワークスペース、Miro 連携、提案書コーパスの投入、音声の複製、定時の自律発話。
いずれも 4 日目以降。理由は `system-prompt.md` の設計を先に本人の採点で固めるため。

## 応答 JSON の要点

```json
{ "speak": "...", "text": "...", "diagram": null, "sheet_update": { "field": "customer", "value": "..." }, "stage": "problem", "next_action": null }
```

`speak` は 60 字以内で問いは一つ。`diagram` は構造・流れ・比較のときだけ。詳細は `system-prompt.md` 第 2 節。
