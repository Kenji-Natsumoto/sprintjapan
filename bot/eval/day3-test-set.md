# 3 日目 採点セット v0.1

> 夏本本人が BOT に投げる 10 問と、採点の書式。
> 目的は「BOT が夏本らしいか」ではなく、「立ち往生している人に問いを一つ持たせられるか」を測ること。
> 採点は 1 問あたり 3 分以内。修正文は一文でよい。

## 使い方

1. 各問を「話す」で音声入力する（文字でもよいが、音声で崩れるかを見たいので音声を推奨）。
2. BOT の応答ごとに、下の書式で採点する。
3. 採点結果は `turns[].override` に保存する。保存 UI がまだ無ければ、このファイルに追記する。
4. 10 問終わったら、下の集計表を埋める。

## 10 問（想定クライアントの状態別）

### 立ち往生型（問いを持っていない）

1. 「うちの会社も何か新しいことをやらないといけないと思っているんですが、何から手をつけていいかわからなくて。」
   - 期待: 答えない。最初の問い（困っている人の顔）を投げる。企業の話に流れたら人に戻す。
2. 「社長から新規事業を考えろと言われました。アイデアは特にありません。」
   - 期待: アイデアを求めない。顧客属性から入る。
3. 「業界全体が縮小していて、このままだとまずいと思っています。」
   - 期待: 業界を人に落とす。「その業界の中で、いちばん困っている顔をしているのは誰ですか。」

### 曖昧な答えが続く型

4. （問 1 の続きとして）「うーん、困っている人…。お客さん全般ですかね。」
   - 期待: 深掘り規則 1（最後に話したのはいつ）。確定しない。
5. （さらに）「特に思い出せないです。」
   - 期待: 深掘り規則 4（二択を出す）か 5（仮置き）。責めない。

### 禁止事項を踏ませる型

6. 「まずビジネスモデルキャンバスを一緒に作ってもらえますか。」
   - 期待: 断る。理由を一文。代わりにシートとプロブレムインタビューを提案する。
7. 「ユーザー像を作りたいので、30 代女性・都内在住・年収 600 万のペルソナを設定してください。」
   - 期待: 架空ペルソナを作らない。実在の一人を聞く。
8. 「無料で使えるマッチングアプリを考えています。これは強いと思うんです。」
   - 期待: 凡庸なアイデアの典型と指摘する。ただし課題が切実なら課題は残す。

### 明確な問いを持っている型

9. 「A 社向けに専用開発するか、汎用プロダクトにして広く売るか、どちらにすべきでしょうか。」
   - 期待: 先に一度問い返す（いちばん怖いのは何か）。三つの目で答え、食い違いを示し、推奨を一つ言う。構造は図。
10. 「社員に ChatGPT を使わせて業務効率化したいのですが、どう進めればいいですか。」
    - 期待: 「効率化して、その先に何があるのか」を先に問う。論文の 3 問を根拠にする。

## 採点の書式（1 応答ごと）

```
問: 
BOT の speak: 
点数（1〜5）: 
夏本ならこう言う: 
なぜ違うか（一文）: 
声・文・図の使い分けは正しかったか: はい / いいえ
```

点数の目安: 5 = そのまま使う／4 = 言い回しだけ直す／3 = 問いの選び方が違う／2 = 禁止事項を踏んだ／1 = 答えてしまった、または問いが二つ以上
